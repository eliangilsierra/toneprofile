# Frontend Architecture

Decision records: [ADR-012](../decisions/ADR-012-nextjs-frontend.md) (Next.js),
[ADR-013](../decisions/ADR-013-i18n.md) (i18n), [ADR-014](../decisions/ADR-014-styling.md)
(styling), [ADR-015](../decisions/ADR-015-motion.md) (motion),
[ADR-016](../decisions/ADR-016-mock-backend.md) (mock backend).

## 1. Stack

| Concern | Choice | Why |
|---|---|---|
| Framework | Next.js 16.3 (App Router, Turbopack), React 19.2 | Static marketing pages + app shell in one project; `proxy.ts` for locale negotiation; rewrites to the backend |
| Language | TypeScript strict (`noUncheckedIndexedAccess`) | |
| Styling | Tailwind CSS v4 with CSS-variable tokens | Tokens in one file; no runtime CSS-in-JS |
| i18n | next-intl 4 (en, es) | Server + client translations, ICU plurals, typed keys |
| Server state | TanStack Query 5 | Polling async jobs, caching, retries |
| Forms | React Hook Form + a small typed resolver | Validation is trivial; Zod was removed to save ~50 KB gzip |
| API client | `openapi-fetch` + types generated by `openapi-typescript` from `docs/api/openapi-v1.yaml` | One contract, no hand-written DTOs |
| Motion | Motion for React via `LazyMotion` + `m` (features loaded async) | Layout morphs for the translation |
| Charts | SVG + `d3-scale`/`d3-shape` | Tiny, exact control; loaded only with results |
| Waveform | Canvas 2D; decoded at 8 kHz with `OfflineAudioContext` | Bounded memory for 10-minute files |
| Mock backend | MSW 2 (browser + node) | Real HTTP calls against the contract |
| Tests | Vitest + Testing Library, Playwright + axe-core | |

Rejected: shadcn/ui theme and Radix (no component needed them yet), Zustand (no cross-feature
client state), Zod (see above), GSAP/Lenis (Motion covers it; scroll hijacking hurts a11y),
React Three Fiber/WebGL (cost/battery/a11y — revisit in V2), chart libraries, Storybook (the
internal `/lab` route instead).

## 2. Structure

```text
src/
├── app/
│   ├── layout.tsx, not-found.tsx, globals.css, fonts.ts, icon.svg
│   └── [locale]/
│       ├── layout.tsx                 <html lang>, metadata, NextIntlClientProvider, MotionProvider
│       ├── (marketing)/               static: landing, sign-in, methodology, legal/[doc], lab;
│       │                              examples/ (own providers: reads /v1/examples)
│       ├── (app)/                     client-driven app: tones, tones/new, tones/[id], tones/[id]/sheet
│       └── [...rest]/                 localized 404
├── proxy.ts                           locale negotiation (next-intl middleware)
├── i18n/                              routing, navigation, request config, typed messages
├── features/                          one folder per product area (create-tone, generation, result,
│                                      tone-profile, preset, feedback, library, examples, landing,
│                                      shell, lab)
├── content/                           long-form pages as typed modules per locale (methodology,
│                                      legal); en/es structure parity enforced by a test
├── ui/                                design-system primitives
├── motion/                            tokens, provider, primitives
├── lib/api/                           client, generated schema, types, errors, query keys, backend-ready
├── lib/audio/                         file checks, preview decoding
├── lib/format/                        time, frequency, device parameter formatting
├── mocks/                             demo backend (fixtures, engine, handlers) — mock mode only
└── test/                              Vitest setup and render helpers
messages/en.json, es.json              catalogues (identical keys, enforced by a test)
tests/e2e/                             Playwright specs
scripts/                               measurement scripts
```

Boundaries: `ui/` and `motion/` import nothing from `features/`; features talk to the backend only
through `lib/api`; nothing outside `src/mocks` and the mock bootstrap imports mock code.

## 3. Rendering

| Route | Rendering | Notes |
|---|---|---|
| `/[locale]` landing, `/sign-in`, `/lab` | Static (SSG per locale) | Client islands: hero illustration, translation demo, locale switcher |
| `/tones`, `/tones/new` | Static shell, client data | |
| `/tones/[id]`, `/tones/[id]/sheet` | Dynamic shell, client data | `ResultView` and `Fingerprint` are lazy chunks |
| `/methodology`, `/legal/[doc]` | Static (SSG per locale × document) | Server components only; content from `src/content` |
| `/examples` | Static shell, client data | `/examples/[slug]` (+ `/sheet`) dynamic shell; reuses `ResultView` with `variant="example"` |

`setRequestLocale` is called in every layout and page so next-intl doesn't force dynamic rendering.

## 4. Data flow and async jobs

```text
component → TanStack Query hook → openapi-fetch (await backendReady) → /api/v1/*
   mock mode:  MSW service worker → src/mocks/handlers.ts (contract implementation)
   http mode:  next.config rewrites → TONEPROFILE_API_URL/v1/*
```

- Generation progress: `useGeneration` polls at the backend's `poll_after_ms` until a terminal
  status, also in background tabs. No progress percentages; elapsed time is computed from the
  server's `created_at`.
- Step findings are structured `StepSummary` objects rendered by `useStepDetail` → localized and
  never embellished by the UI.
- Uploads: ticket → direct PUT → complete → poll probe (`uploadReference`).
- Errors: `ApiError` normalises problem+json and network failures; `ProblemState` maps codes to
  localized copy and actions (retry only when `retryable`; hints such as `choose_other_section`,
  `add_excerpt`).
- `backendReady` (mock mode) lets pages render immediately while requests wait for MSW to start.

## 5. i18n

- Locales `en` (default) and `es`; URL prefix always present; `Accept-Language` + cookie
  negotiation in `proxy.ts`.
- Message keys typed from `en.json`; a unit test enforces identical keys and ICU arguments in both
  catalogues.
- Backend prose (tone summary, explanations, claim statements) is generated in the locale requested
  at generation time and marked with `lang`; when viewed in another locale the UI says so.
- SEO: the locale layout sets no `alternates` (children would inherit a wrong canonical). Each
  indexable page (landing, new tone, examples, methodology, legal) sets its own canonical plus
  `en`/`es`/`x-default` hreflang via `alternatesFor` (`src/i18n/metadata.ts`). Personal and utility
  pages (library, results, sheets, sign-in, lab) are `noindex` with no canonical. Covered by
  `tests/e2e/seo.spec.ts`.

## 6. Mock mode

`NEXT_PUBLIC_API_MODE=mock` (default) runs the whole product on fictional data:
five fictional songs, a time-based deterministic job engine, localStorage persistence, and
scenario triggers (see [ADR-016](../decisions/ADR-016-mock-backend.md)). A persistent
"Demo · simulated analysis" marker is shown; preset files are unavailable in the demo (the dial-in
sheet works).

## 8. Accessibility

Semantic landmarks and headings, skip link, visible focus (amber outline), keyboard-complete
combobox and toggles, `role="meter"`, text alternatives for charts (band buttons + data table),
live regions for job progress, reduced-motion support, WCAG AA contrast (axe runs in E2E).

## 9. Testing

| Level | Tooling | What |
|---|---|---|
| Unit | Vitest | Mock job engine, formatters, file checks, validation, message catalogue parity |
| Component | Vitest + Testing Library + MSW node | Song search combobox, fingerprint |
| E2E | Playwright (desktop + mobile smoke) + axe | Primary journey (en/es), library, retry, refusal without evidence, no-guitar, validation, cancel, 404 |

Run: `npm test`, `npm run e2e` (after `npm run build`).
