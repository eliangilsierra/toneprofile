# ADR-013 — English and Spanish from the MVP (next-intl)

- Status: accepted
- Date: 2026-09-29

## Context

The product owner asked for English + Spanish in the MVP. Guitar terminology mixes languages
(gain, crunch, preset) and device labels must match the hardware.

## Decision

- next-intl 4 with locale prefix routing (`/en`, `/es`), `Accept-Language`/cookie negotiation in
  `proxy.ts`, typed message keys from `messages/en.json`.
- Device labels, parameter names and units are never translated (they must match the device).
- The backend receives `locale` with each generation and writes prose (summary, explanations,
  claim statements) in that language; everything else is structured data localized by the client.
- A unit test enforces identical keys and ICU arguments across catalogues.

## Consequences

Every UI string lives in the catalogues; new copy needs both languages. Prose viewed in another
locale than it was generated in is labelled (and marked with `lang`).
